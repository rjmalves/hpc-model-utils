# Accumulated Learnings: cli-resilience plan (through Epic 02)

## Patterns Established

- **Two-tier validation pattern** (Epic 01): Semantic validation in `app/validation.py` (per-command) + `click.ParamType` subclasses in `app/click_types.py` (argument-parse time). Still not fully wired into `app/cli.py`.
- **Lazy ModelFactory import inside validators** (Epic 01): Both `validate_model_name()` and `ModelNameType.convert()` import `ModelFactory` inside the function body. Required because model modules self-register at import time. Any future validator touching `ModelFactory` must follow this.
- **Module-level compiled regex** (Epic 01): `validate_queue_name()` uses `_QUEUE_NAME_RE = re.compile(...)` at module scope. Apply to any future regex validators.
- **Fail-fast validation** (Epic 01): Per-command validators stop at the first failure. Do not introduce error-accumulation patterns.
- **Decomposed SLURM monitoring** (Epic 02): `follow_submitted_job()` replaced the fragile compound shell one-liner with three distinct Python helper functions — `_job_in_queue()`, `_tail_stdout()`, and the post-completion block — each independently testable. See `app/utils/scheduler.py` lines 191-244.
- **`deque(fh, maxlen=N)` for line-capped file reads** (Epic 02): `read_job_output_files()` reads potentially large SLURM output files using `collections.deque` with `maxlen=10000`, avoiding full file load into memory. Capped at 10 000 lines. See `app/utils/scheduler.py` line 108.
- **Best-effort diagnostics return `None`, never raise** (Epic 02): `get_job_completion_info()` wraps its entire body in `try/except Exception` and returns `None` on any failure. Post-completion diagnostic functions that call external tools (sacct, etc.) must follow this contract — failure signals absence of data, not a monitoring failure.
- **`run_in_terminal()` for all subprocess calls** (Epic 02): Every shell command (`squeue`, `sacct`, `tail`) goes through `run_in_terminal()`. Direct `subprocess.run()` is not used anywhere in scheduler-related code. File reads (`stdout.modelops`, `stderr.modelops`) use Python's `open()` to avoid `last_lines_diff` dedup suppression.
- **`@dataclass` for structured return types** (Epic 02): `JobCompletionInfo` and `JobOutputFiles` are module-level dataclasses with explicit typed fields and inline comments documenting value format (e.g., `"0:0"`, `"4096K"`). See `app/utils/scheduler.py` lines 13-29.
- **Sacct `.batch` suffix filtering** (Epic 02): `sacct` output includes `12345.batch` step lines alongside the base `12345` line. `get_job_completion_info()` filters by exact job_id string equality (`parts[0] == job_id`) to exclude step lines.

## Architectural Decisions

- **Post-completion read is always executed, even if monitoring loop never ran** (Epic 02): The fix for fast jobs (< 2s) is that `read_job_output_files()` and `get_job_completion_info()` are called unconditionally after the `while` loop exits — whether the loop ran zero, one, or many iterations. The monitoring loop body becoming a no-op does not suppress post-completion diagnostics.
- **`click.BadParameter` as interim error type** (Epic 01): Still not replaced by `ValidationError`. Epic 03 must introduce the custom hierarchy. Tests written for Epic 04 must check for Click's exit code 2 and the "Error: Invalid value for" prefix until Epic 03 runs.
- **Validation wired to CLI is incomplete** (Epic 01, deviation persisting): `app/cli.py` does not call any validator functions and does not use `ModelNameType`, `S3PathType`, or `PositiveIntType`. The wiring step must be completed before Epic 03's error handler refactor touches `app/cli.py`.
- **sacct ordering relative to output file read** (Epic 02): Post-completion sequence is fixed as: `read_job_output_files()` -> log stdout -> log stderr -> `get_job_completion_info()` -> log state. sacct is queried last because it may be slow (accounting DB latency). Output files are read first because they are local and faster.
- **`squeue -h -j` raises on non-zero exit, sacct silently returns `None`** (Epic 02): The asymmetry is intentional. `squeue` failure during the monitoring loop means the monitoring is broken and must stop (RuntimeError). `sacct` failure after completion is a degraded diagnostic and must not prevent the function from returning.

## Conventions Adopted

- All post-completion diagnostic functions have signature returning `Type | None` and never raise; wrap body in `try/except Exception: return None`.
- `follow_submitted_job()` post-completion log prefixes: stdout block uses `"=== Final stdout.modelops (...) ==="`, stderr lines use `"  STDERR: {line}"`, sacct warning uses `"WARNING: Job {job_id} ended with state {state}"`.
- SLURM output file names `stdout.modelops` and `stderr.modelops` are constants defined inline as local variables in the functions that use them (not in a constants module). If they need to change, both `submit_job()` SLURM flags and `read_job_output_files()` defaults must be updated together.
- Test fixtures for `follow_submitted_job` patch `app.utils.scheduler.read_job_output_files` as a unit rather than patching `open()` and `Path.exists()`. This avoids coupling test setup to the internal implementation of file reading.
- The monitoring poll interval (2.0 seconds) and the sacct timeout (10 seconds) are magic numbers local to the functions, not constants. If they become tunable, they should be extracted to `app/utils/constants.py`.
- Validation primitives: signature `def validate_X(value: T, param_name: str = "default") -> None`, raise `click.BadParameter` on failure (Epic 01).
- Custom Click types: named `<ConceptName>Type`, `name` attribute uses `UPPER_SNAKE` (Epic 01).

## Surprises and Deviations

- **Epic 02 was executed without a git diff range**: The plan commit that marks epic-02 as started does not exist — all scheduler.py changes appear to have been implemented in a single working session on the `localstack` branch without intermediate commits demarcating the epic boundary. The `git log` for `app/utils/scheduler.py` shows the pre-plan history (`4cb63e8 better log following`) and then the current state with no in-between commits. Learnings were extracted by comparing `git show 206c9b5:app/utils/scheduler.py` (state at epic-01 completion) against the current file.
- **`submit_job()` was also refactored in the same pass** (not in any ticket): The old `submit_job()` had a latent bug — `groups` was used outside the `if match:` block, risking `UnboundLocalError`. The new code uses the walrus operator `if match and (groups := match.groups())`. This change was not in any ticket spec but is beneficial. Epic 04 test-012 (slurm monitoring tests) should add a test for `submit_job()` to cover this previously untested path.
- **`wait_cancelled_job()` still uses the old compound shell one-liner**: `wait_cancelled_job()` in `app/utils/scheduler.py` (lines 257-269) was explicitly out of scope for Epic 02, and it was not touched. It still uses `f"while squeue | grep {job_id} > /dev/null ;do"`. Epic 03 or a follow-up cleanup ticket should apply the same decomposition pattern to `wait_cancelled_job()`.
- **`type_safety: 0.5` across all tickets in both epics**: The project has no `mypy` or `pyright` baseline. All quality scores show `type_safety: 0.5` (neutral). The new dataclasses and `str | None` union types in scheduler.py would benefit from mypy checking. Epic 04 or a standalone chore should add mypy to CI.
- **`test_delta: 0.0` for tickets 001, 003, 004 in Epic 01** (persists): Tests for validation primitives and Click types still not written. Epic 04 ticket-011 owns this.
- **Ticket ordering deviation**: The spec for ticket-007 states post-completion ordering as: output files -> sacct. The implementation follows this. However, the spec's `Implementation Guide` suggested ordering was "read output files -> log stdout -> log stderr -> sacct query -> log completion info" — the implementation matches this exactly, including the sacct-last placement that was only implied in the guide, not stated as a hard requirement.

## Recommendations for Future Epics

- **Epic 03 (Structured Errors) — complete CLI wiring before error hierarchy refactor**: `app/cli.py` still has no validator calls and no `ModelNameType`/`S3PathType`/`PositiveIntType` argument types. The recommended order before Epic 03 starts: (1) wire validators, (2) add Click types, (3) then replace `click.BadParameter` with `ValidationError`. Doing step 3 first forces two passes over `app/cli.py`.
- **Epic 03 — `SlurmError` can reference `JobCompletionInfo`**: The `JobCompletionInfo` dataclass (`app/utils/scheduler.py`) carries `state`, `exit_code`, and `elapsed`. Epic 03's `SlurmError` should accept an optional `JobCompletionInfo` instance as a field, enabling the error handler to log structured SLURM context without parsing log strings.
- **Epic 03 — `squeue` RuntimeError needs an error class**: `follow_submitted_job()` raises a generic `RuntimeError` when `squeue` fails. Epic 03 should introduce a `SlurmMonitoringError` (or similar) subclass so the CLI error handler can distinguish SLURM infrastructure failures from model execution failures.
- **Epic 04 (Test Coverage) — ticket-012 must add `wait_cancelled_job()` tests**: `wait_cancelled_job()` was not touched in Epic 02 and has no tests. ticket-012 is scoped to SLURM monitoring; it should cover `wait_cancelled_job()` and `cancel_submitted_job()` as well as the new `get_job_completion_info()` / `read_job_output_files()` functions (the latter already have tests, but `wait_cancelled_job` does not).
- **Epic 04 — use `tmp_path` + `monkeypatch.chdir()` for file I/O tests**: The `TestReadJobOutputFiles` class in `tests/unit/test_follow_submitted_job.py` demonstrates the canonical pattern for testing functions that read files from the working directory: `monkeypatch.chdir(tmp_path)` + `(tmp_path / "filename").write_text(...)`. Reuse this pattern in ticket-011 if any validation primitive tests need temp file access.
- **Epic 04 — patch `read_job_output_files` as a unit in `follow_submitted_job` tests**: Do not patch `open()` or `Path.exists()` when testing `follow_submitted_job`. Patch `app.utils.scheduler.read_job_output_files` to return a pre-built `JobOutputFiles` instance. This is the pattern established in `TestFastJob`, `TestNormalJob`, etc.
- **Epic 05 (Observability) — timing decorator must wrap outside the monitoring loop**: Per the constraint established in Epic 01, timing calls must wrap the entire function body. For `follow_submitted_job`, this means timing starts before the first `_job_in_queue()` call and ends after `get_job_completion_info()` returns. The elapsed time logged by sacct (`completion_info.elapsed`) is the job's wall time inside SLURM; the function's own timing measures total monitoring overhead.
